# Component specimen verification — proposed, not executable

Status: research prepared; project planning, reference selection and creator
dispatch **not started**. This is a scoped work proposal, not a planning receipt,
rights grant, approved reference pack, Owner decision or implementation evidence.

## Purpose and boundary

Test whether the Korean-service analysis improves concrete component craft,
readability and behavior in a separate, disconnected KSR verification project.
Do not edit a product, reuse another project's approval, or interpret the
Owner's authorization to continue research as visual selection.

Three useful starting families are proposed below. These are verification
subjects, not the three shortlisted theses of a design run, and do not replace
the default exact-three 3×3 exploration contract.

| Proposed subject | Research lookup | Why it is useful / limit |
| --- | --- | --- |
| Briefing card and reader | `reference library --component briefing-card --details` | Date/topic hierarchy, readable summary and original-source transition. Financial briefing imagery and domain claims must not transfer automatically. |
| Numeric list and issue sheet | `reference library --component watchlist-detail --details` | Row rhythm, numeric alignment, status contrast and list/detail relationship. A stock watchlist is not proof of a general comparison table. |
| Search palette and tabs | `reference library --component mixed-search-palette --details` | Distinguishing entities, news and related queries. The source has only one static frame: keyboard, transitions and mobile reflow are unknown. |

The lookup returns the exact UI Bowl frame URLs, capture digests and observations
from the [sealed study](ui-bowl-korea-component-study-2026-09-22.json).
No source image is distributed here. Full source-named analysis is restricted
to researchers, critics and the Owner; only the normal creator-safe projection
may reach a creator after the project reference gates.

   actual scope. None is asserted by this proposal. Planning evidence must be

   Research-only captures and their manual peer review are not that contract.

   Owner's anchor/support/grammar choice and the resulting ready reference pack.

   adapters, target behavior and the applicable baseline/visual authority.

## Proposed validation, not executed evidence

For each eligible target specimen, bind concrete typography, color, material,
spacing and component anatomy values in component specs. Use synthetic Korean
content, including long titles, mixed numerals, missing/partial/empty/error
states and visible source/disclosure boundaries.

Run actual native click and keyboard/focus assertions, text clipping and
overlap checks, contrast, semantic controls and viewport reflow at three
distinct widths (proposed 390/768/1440px), plus critical intermediate widths.
Record screenshots, browser report and traces with private retention where
needed. These are **target test proposals**, never claimed source behaviors.
An independent critic must compare implemented craft and information hierarchy
to the authorized projection, while checking source-copying and project fit.

Stop at the existing direction/color/exact-artifact Owner gates. Only the
approved, independently audited artifact can enter the applicable systemization
route. No shared production component or successful Playwright run exists yet.
