# UI Bowl 실화면 연구: 취향을 지우지 않고 위계를 설계하기

관찰일: 2026-09-10 (Asia/Seoul). 상태: **관찰 연구, 독립 검토·Owner 시각 승인 없음**.
대상 독자: KillSlopRouter 내부 연구자·검토자·Owner. 이 문서는 creator용 프롬프트나 승인된 reference pack이 아니다.

## 이번에 실제로 한 일

UI Bowl을 브라우저에서 열고, 실제 확대 화면을 보며 6개 제품의 19개 서로 다른 프레임을 판독했다. 화면 목록의 제목이나 커뮤니티 해설만 읽고 판정하지 않았다. 동일 제품의 상태 변화도 포함하므로, 19개는 독립 디자인 19종이라는 뜻이 아니다.

- 업무 화면: Museby 2, Microsoft Clarity 2, 당근 비즈니스 2.
- 비교·선택 화면: Npay 부동산 4, 카드고릴라 6.
- 정서적 표현이 강한 모바일 화면: Moodee 3.
- 별도 제외: 토스 홍보 프레임 1. 29CM 메인은 멤버십 제한으로 관찰하지 못했다.
- 정확한 프레임 ID, 출처, 판독한 상태는 [표본 기록](ui-bowl-task-design-samples-2026-09-10.json)에 남겼다.

일반 탐색 UI와 사이트가 노출한 링크만 사용했다. 결제, 내보내기, 댓글, 북마크, MCP 설치, 접근 제한 우회는 하지 않았다. 이미지·에셋·원문 화면을 저장소에 복제하지 않는다. [UI Bowl의 저작권 고지](https://uibowl.io/)에 따라 구조적 원리와 출처를 기록한다. 브라우저 관찰은 원본 이미지의 보존·해시 고정 증거와 다르다.

이 기록은 [9월 4일 연구](ui-bowl-popular-design-study-2026-09-04.md)를 재실행했다고 주장하지 않는다. 새 관찰이며, 이전 표본과 중복 여부를 모두 검증하지 않았으므로 두 연구의 수를 합산하지 않는다. 모델 가중치를 재훈련한 것도 아니다.

## 가장 중요한 수정

**세련됨을 특정 색·서체·카드 형태로 정의하지 않는다. 사용자에게 필요한 판단의 순서와 시각적 개성을 함께 설계한다.**

기존 연구에도 맥락·색 역할·타이포그래피 질문은 있었다. 이번의 보강점은 실제 상태별 반례다. 업무 제품도 푸른 바탕과 그림자를 쓸 수 있고, 소비자 제품도 비교 단계에서는 절제된 표를 쓴다. 하나의 제품 안에서도 여백, 밀도, 강조의 크기가 달라진다. 따라서 새로운 공통 테마 하나를 추가하는 것으로는 획일화 문제가 해결되지 않는다.

## 1. Museby: 브랜드보다 업무 상태가 먼저 읽혀야 하는 순간

출처: [펼친 탐색 영역과 캠페인](https://uibowl.io/website?imgId=cmttba5ql000ikz04cmgzxnd2), [축소 탐색 영역과 복수 캠페인](https://uibowl.io/website?imgId=cmttba5r8000kkz045ejrnu24). UI Bowl 표기: 2026-09.

**관찰.** 밝은 작업 면, 주황색 생성 동작, 옅은 선택 배경, 어두운 시작 안내 배너가 공존한다. 진행 중인 캠페인과 완료 영역이 분리된다. 두 번째 화면에서는 탐색 영역이 아이콘 폭으로 줄고, 두 캠페인이 같은 정보 순서로 놓인다. 상태와 기간은 카드 내부의 보조 위계다.

**추론 — 중간 확신.** 처음 사용하는 사람에게는 안내가, 재방문자에게는 진행 중인 객체가 중요하다. 상태별 분리와 반복 슬롯은 다음에 열 대상을 찾는 데 유리할 수 있다. 축소된 탐색 영역이 실제로 언제·어떻게 전환되는지는 검증하지 않았다.

**미감에서 배울 점.** 모든 면을 같은 명도로 만들지 않고, 강한 배너·약한 탐색 면·주 작업 면 사이에 대비를 둔다. 주황색을 배경 전체에 펴지 않아도 정체성이 유지된다. 대신 시작 안내가 항상 큰 영역을 차지한다면 숙련자의 작업을 밀어낼 위험도 있다.

**적용 금기.** 캠페인 카드의 정보가 많아졌는데도 이 낮은 밀도를 그대로 복사하지 않는다. 내부 관리자 화면에 시작 안내용 히어로를 영구 기본값으로 만들지 않는다.

## 2. Clarity: 카드를 없애는 것이 아니라 수치에 근거와 동작을 붙인다

출처: [사용자 불편 신호](https://uibowl.io/website?imgId=cmt17w3iw001fjy04fiwqu9a6), [방문 추이 팝오버](https://uibowl.io/website?imgId=cmt17vmck00qhl504uxthpwi4). UI Bowl 표기: 2026-08.

**관찰.** 상단에 기간·필터와 요약 수치, 아래에 사용자·불편 신호·관심 목록 영역이 놓인다. 비율 옆에 세션 수와 녹화 진입으로 읽히는 아이콘이 있다. 추이 프레임은 대시보드를 남겨둔 채 수치 근처에 차트를 띄운다. 푸른 바탕, 흰 패널, 보라·자홍 데이터, 그림자가 함께 사용된다. 관심 목록이 빈 상태도 보인다.

**추론 — 중간 확신.** 전체 규모를 먼저 보고 문제 세션을 좁혀 보는 작업에는 요약→세부→근거의 연결이 유용할 수 있다. 이는 실제 세션 재생 성공이나 지표의 정확성을 검증한 결론은 아니다.

**미감에서 배울 점.** 크기·굵기가 큰 값과 작은 단위·분모의 대비가 수치 위계를 만든다. 같은 카드 안에도 강조 강도가 다르다. 부드러운 깊이와 색이 정보를 구분하는 역할을 한다면 그 자체를 슬롭으로 판정할 이유가 없다.

**적용 금기.** 모든 KPI에 차트를 붙이거나, 실제 근거가 없는 재생 아이콘을 만들지 않는다. 저빈도 사용자를 위한 화면에 이 밀도를 그대로 이식하지 않는다. 빈 관심 목록의 큰 면적도 항상 최적이라고 단정하지 않는다.

## 3. 당근 비즈니스: 0을 멋진 샘플 데이터로 덮지 않는다

출처: [관리자 홈 상단](https://uibowl.io/website?imgId=cmso68mja000el704vilcy6lq), [같은 홈 하단](https://uibowl.io/website?imgId=cmso68mk2000gl704j44a8xph). UI Bowl 표기: 2026-08.

**관찰.** 사업자 맥락과 탐색 영역이 유지된다. 상단은 정보 채우기 진행도와 추천 작업, 하단은 기간이 있는 통계와 소식·후기 영역이다. 통계는 0이며, 소식과 후기도 비어 있다. 소식 영역에는 작성 동작이 있다. 브랜드 주황과 별개로 선택된 통계는 푸른 테두리·면으로 구분된다.

**추론 — 중간 확신.** 새 사업자는 숫자를 감상하기보다 운영을 시작할 다음 행동이 필요하다. 완료하지 않은 준비와 아직 생기지 않은 성과를 구분하면 현재 상태를 이해하기 쉬울 수 있다.

**미감에서 배울 점.** 모든 버튼을 브랜드색으로 칠하지 않는다. 제목, 제한된 색 강조, 옅은 면, 정렬만으로도 읽는 순서를 만들 수 있다. 여백은 비어 있는 사업자의 사실과 다음 행동을 드러내는 데 쓰인다.

**적용 금기.** 이 신규·빈 상태를 성숙한 고밀도 ERP의 기본 구성으로 삼지 않는다. 0, 미연결, 미승인, 오류를 모두 같은 빈 카드로 표현하지 않는다. 두 프레임은 상·하단 관찰이지 서로 다른 사용자 상태를 증명하지 않는다.

## 4. Npay: 질문 화면과 결과 화면의 밀도가 같을 필요가 없다

출처: [서비스 진입](https://uibowl.io/website?imgId=cmrvqfnmp0009kz04n4z1m62g), [동의 화면](https://uibowl.io/website?imgId=cmrvqfnnn000bkz04x8vuiquh), [목적 선택](https://uibowl.io/website?imgId=cmrvqfnoe000dkz04l8elzhlk), [결과](https://uibowl.io/website?imgId=cmrvqh889000al704eue8whlx). UI Bowl 표기: 2026-07. 금리·한도는 디자인 관찰용 과거 화면이며 금융 추천 근거가 아니다.

**관찰.** 진입에는 상품 유형 탭과 서로 다른 시작 경로가 있다. 동의와 목적 질문은 별도 프레임이다. 목적 선택은 적은 수의 행으로 구성되고 한 선택지에는 적용 조건이 덧붙는다. 결과는 요약, 대상 정보, 상품 수와 정렬, 수치와 조건이 있는 목록으로 조밀해진다. 상품 조건이 바뀔 수 있다는 안내도 목록 앞에 있다.

**추론 — 중간 확신.** 입력에서는 현재 질문의 선택지가, 비교에서는 동일 기준의 수치와 조건이 중심이어야 한다. 한 화면에 필요한 밀도는 서비스 전체의 스타일 이름보다 그 단계의 판단에 좌우될 수 있다.

**미감에서 배울 점.** 넓은 화면에서도 본문 폭을 제한해 질문과 결과의 읽기 축을 유지한다. 녹색은 행동과 수치 강조, 회색은 배경과 보조 설명에 사용된다. 색상 수보다 역할·명도 대비·반복 정보의 정렬이 중요하다. 실제 대비 수치는 측정하지 않았다.

**적용 금기.** 전문가의 반복 입력에 질문 하나씩 강제하는 위저드를 무조건 적용하지 않는다. 신뢰가 불확실한 결과를 녹색으로 칠해 확정값처럼 보이게 하지 않는다. UI Bowl의 '대출 조건 입력'이라는 분류만 믿으면 진입·동의 화면을 실제 입력 폼으로 잘못 셀 수 있다.

## 5. 카드고릴라: 비교표는 빈 상태부터 비교표여야 한다

출처: [빈 비교 슬롯](https://uibowl.io/website?imgId=cmr360eyd000qjt04zk847cz7), [신용카드 선택](https://uibowl.io/website?imgId=cmr360ez2000sjt04zqbm7ex4), [체크카드 선택](https://uibowl.io/website?imgId=cmr360ezt000ujt04sar13zkz), [검색](https://uibowl.io/website?imgId=cmr360f0j000wjt04lct4bypt), [1개 선택](https://uibowl.io/website?imgId=cmr360f18000yjt041hanfpkv), [3개 선택](https://uibowl.io/website?imgId=cmr360f1y0010jt047oqepqjd). UI Bowl 표기: 2026-07.

**관찰.** 빈 화면부터 세 개의 후보 슬롯이 있다. 선택 화면은 카드 유형 탭, 발급사 필터, 검색, 목록을 구분한다. 하나를 선택하면 그 열만 채워지고 다른 두 슬롯은 남는다. 세 개가 채워진 화면에서 비용·조건·혜택의 행과 각 후보의 열이 정렬된다. 노랑 계열의 브랜드 표현과 별개로 세부 보기 동작은 검정이다.

**추론 — 중간 확신.** 빈→부분→채워짐에서 공간적 대응을 보존하면 무엇을 더 선택하고 무엇을 비교하는지 이해하기 쉬울 수 있다. 프레임 간 변화는 관찰했지만 실제 선택·삭제 동작은 이 제품에서 실행하지 않았다.

**미감에서 배울 점.** 표를 카드들로 무조건 분해하지 않는다. 같은 축의 정렬, 제목과 조건의 굵기 차이, 제한된 행사 강조만으로도 비교 화면의 질서가 생긴다. 이미지의 개성은 남겨 두고 비교 필드는 규칙적으로 정렬한다.

**적용 금기.** 세 개라는 개수를 모든 제품의 정답으로 삼지 않는다. 긴 조건이 있으면 행 대응·제목 손실·모바일 재배치를 별도 검증해야 한다. 비교표의 모바일 상태는 이번에 관찰하지 않았다.

## 6. Moodee: 개성은 장식만이 아니라 대화의 맥락이 될 수 있다

출처: [사용량 안내](https://uibowl.io/name/%EB%AC%B4%EB%94%94%20Moodee?imgId=cmsda5sc90003ju041xdyg7ek), [다른 사용량 상태](https://uibowl.io/name/%EB%AC%B4%EB%94%94%20Moodee?imgId=cmsda5sd00005ju045ndpr4nj), [대화와 감정 맥락](https://uibowl.io/name/%EB%AC%B4%EB%94%94%20Moodee?imgId=cmsda5sdk0007ju04xhffnqpm). UI Bowl 표기: 2026-08.

**관찰.** 어두운 녹색 계열의 배경과 캐릭터, 반투명 대화 요소, 감정을 나타내는 태그가 보인다. 이용량 안내는 배경을 어둡게 남기고 밝은 하단 면으로 분리된다. 보라→파랑 그라데이션 동작과 종이비행기 상징이 있다. 안내가 없는 프레임에서는 감정 맥락과 답장 영역이 드러난다.

**추론 — 중간 확신.** 정서적 기록에서 배경·캐릭터·대화의 연결은 단순 통계 입력과 다른 경험을 만들 수 있다. 다만 실제 편안함, 치료 효과, 유지율, 접근성은 증명하지 않는다. 사용량 숫자의 다른 상태도 단일 세션의 시간 순서라고 단정하지 않는다.

**미감에서 배울 점.** 배경, 재질, 반투명 면, 상징, 색의 흐름이 함께 정체성을 만든다. 이것을 회색 카드와 평문으로 바꾸면 정보가 남아도 경험의 성격은 달라진다. 반대로 어두운 배경 위 작은 텍스트는 실제 가독성 검사가 필요하다.

**적용 금기.** 캐릭터나 숲 배경을 복사하지 않는다. 고위험 승인·오류·비용 안내를 분위기 속에 숨기지 않는다. 감정 서비스의 수익화 화면을 좋은 사용자 경험이라고 자동 승인하지 않는다.

색의 조화에 대한 이번 결론은 특정 HEX 조합이나 만능 배합 공식이 아니다. 관찰된 예에서는 **역할 분리, 강조 면적의 차이, 반복되는 색 관계, 중립 면과 데이터/이미지의 대비**가 중요한 설계 재료였다. 실제 팔레트는 승인된 브랜드와 콘텐츠를 기반으로 후보를 만들고, 상태·대비·색각·실제 화면에서 검증해야 한다.

서체 이름이나 정확한 크기는 정지 이미지로 확정하지 않았다. 적용에서는 먼저 의미별 타이포그래피 역할을 정한 뒤 실제 렌더링한 한글/영문/숫자, fallback, 줄바꿈, 줌으로 검증한다. 레퍼런스의 작은 글자를 그대로 복사하는 일은 학습이 아니다.

## 서비스 기획에서 시안으로 옮기는 최소 흐름

1. 서비스 기획에서 사용자·핵심 객체·판단 순서·위험·반복 빈도를 읽는다. 기존 UI라면 승인 기준선과 실제 화면부터 고정한다.
2. 유지할 개성(색의 역할, 밀도, 형태, 깊이, 이미지, 언어)을 명시하고 이번 변경 범위를 정한다.
3. 연구자는 타깃과 맞는 원리 및 반례를 추출한다. 원본 화면·문구·출처 식별자를 creator의 복제 지시로 전달하지 않는다.
4. 외부 creator는 원리를 타깃 데이터와 흐름으로 재설계한다. 색·폰트만 바꾼 안을 서로 다른 구조적 방향으로 세지 않는다.
5. 독립 critic은 T01–T10을 맥락에 맞춰 검토한다. Playwright는 타깃에서 클릭·키보드·상태·모바일·오버플로·대비 등의 실행 증거를 만든다.
6. Owner가 방향과 시각 기준을 승인한다. KSR는 과정과 근거를 연결하며 직접 생성하거나 스스로 승인하지 않는다.

이 흐름은 설명용이며 새로운 승인 receipt가 아니다. 정식 reference run에는 기존의 기획·권리·provider 분리·source capture·해시·Owner 선택 계약이 필요하다. 현재 노트에는 그 계약을 충족하는 보존 캡처와 독립 검토가 없으므로 곧바로 design-ready pack으로 ingest하면 안 된다.

## 한계와 다음 검증

- 현재 UI Bowl의 인기 표시와 일반 검색을 발견 경로로 사용했다. 전체 인기 순위나 북마크/MAU를 수집·검증한 연구가 아니다.
- 29CM 메인은 현재 접근 제한으로 미관찰, 토스는 홍보 이미지이므로 업무 원리의 근거에서 제외했다. 목록상의 앱 이름과 실제 확인한 화면을 혼동하지 않는다.
- 여섯 제품 중 다섯이 웹이고, 두 제품이 금융 비교다. 모든 업종·연령·스타일·모바일을 대표하지 않는다.
- 대부분 화면은 부분 뷰포트다. 작게 보인 글자의 정확한 서체·px·HEX·대비값은 미확인이다. 파란 클릭 표식 등 수집자가 덧붙인 주석은 제품 디자인 토큰으로 해석하지 않는다.
- 실제 제품의 인터랙션·서버·권한·효과를 실행하지 않았다. UI Bowl 뷰어에서 다음 이미지를 본 것을 원래 제품의 사용자 동작 성공으로 세지 않는다.
- 사람처럼 느껴지는 디자인이라는 평가는 가설이다. 실제 사용자 과제·선호 비교·독립 검토가 있어야 결과 개선을 주장할 수 있다.
- 모델 재훈련, 공식 KSR 연구 완료, 새 gate 배포, 제품 UI 변경, Owner 승인, PR 병합은 이 작업에 포함되지 않는다.

다음 적용의 성공 기준은 레퍼런스를 몇 개 더 보았는지가 아니다. **기존 개성 보존 + 판단/가독성 개선 + 실제 동작 검증 + Owner 선호**를 별도로 확인해야 한다. 스캐너 0건은 이 네 가지의 대체 증거가 아니다.
